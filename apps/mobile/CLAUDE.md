# apps/mobile (Flutter app `pindoro`, org app.pindoro)

Offline-first: progress in Drift (SQLite), city data from read-only SQLite packs.

```
lib/main.dart                  open AppDatabase, pick the initial route, runApp
lib/app/                       shell: PindoroApp, router (the only place that imports screens),
                               TabShell (bottom navigation)
lib/core/                      shared by every feature: routes (paths + RoundSummary), config, format,
                               labels, settings, location, online, toast, page scaffold, launch overlay,
                               database/ (Drift tables, migrations, .drift trigger, SettingsDao)
lib/features/<feature>/data/   DAOs, repositories, stores and providers over the database or packs
lib/features/<feature>/ui/     screens and controllers (Riverpod notifiers), their parts in ui/widgets/;
                               never Drift
                               features: progress (ProgressDao: rounds + answer log + goal days +
                               Pit stop + lesson results; streakProvider, reminders, the daily goal
                               ring and sheet, the top bar, level row, level up), pack (+ the road graph), map (the map,
                               the shared pin-drop and road-trip views), course (the Path), home, setup (welcome,
                               city, area, difficulty), quiz (round), results (results, street),
                               settings, streak, pitstop, me, lesson (lesson, Lesson complete, Final drive,
                               Unit complete), league (the Leagues tab, the name form; data: LeagueDao,
                               LeagueApi, standingProvider), badges (stats, awards, the shelf tile,
                               the reward sheet and BadgeMoments)
lib/features/quiz/ui/round_controller.dart   round state machine; resumes from round_question + answers;
                               questions are NamedStreets (cityStreetsProvider); retries set round.retry_of,
                               Pit stop rounds round.pit_stop
lib/features/pack/data/pack_store.dart       catalog download + sha256/size check -> <docs>/packs/<city>/<version>.sqlite (2 kept)
assets/packs_fixture/          Vake fixture pack (built by `just fixture`, do not edit by hand)
assets/map_styles/             pindoro_{light,dark}.json (generated by `pipeline tiles`)
drift_schemas/                 committed schema dumps, one per schemaVersion
test/drift/                    generated schema helpers + migration test
```

## Conventions

- **Layers, lowest first:** `l10n` → `core` → `features/progress` → `features/pack` →
  `features/map` → `features/course` → `features/league` → `features/badges` → screen features (`home`, `setup`, `quiz`, `results`,
  `settings`, `streak`, `pitstop`, `me`, `lesson`) → `app` → `main.dart`. A file imports its own slice or a lower layer only; screen features never import
  each other. Something two features need moves down (to `core`, or to `progress`/`pack`/`map`).
  `test/architecture_test.dart` enforces this, and that `ui/` never imports Drift; a new feature
  gets a layer there. Imports are `package:pindoro/...` (lint
  `always_use_package_imports`), so every import names its layer. `pindoro_core` is the domain
  layer, so features have no `domain/` folder.
- **Riverpod 3, no codegen.** Plain `Provider` / `FutureProvider` declared next to what they
  provide. `databaseProvider` is overridden in `main()` and in tests. Widgets read with
  `ref.watch` in build, `ref.read` in callbacks.
- **Routing:** go_router, paths in `Routes` (v1-screens.md § Navigation). The tabs are a
  `StatefulShellRoute` (`TabShell`, a `FadeIndexedStack` of one page per branch): `/path` the
  Path, `/` Free play (Home), `/pit-stop`, `/leagues`, `/me`; `go` to one of them switches tab, back on
  another tab goes to the Path first, and each tab page gets its own `PrimaryScrollController` (a
  tap on the open tab scrolls it up; on the Path, to the current stop). Every other route sits on
  the root navigator, over the bar: `/welcome`, `/whats-new`, `/city` (`?course=1` goes on to
  `/start-district`), `/area`, `/difficulty`, `/round`
  (`?round=` resumes, `?retry=` retries, `?pit-stop` plays the Pit stop), `/results`, `/lesson`
  (`?unit=&lesson=`, `&practice=1`, or `?unit=&pit-stop=1`), `/lesson-done?result=`,
  `/drive?unit=` (the Final drive, Jump ahead on a locked unit), `/unit-done?unit=&xp=` (the drive's XP, for its level-up),
  `/unit-guide?unit=` (`&lesson=` opens with that lesson's streets on the map),
  `/league-name`, `/streak`, `/settings`, `/settings/credits`. The app opens on the Path once a course exists
  (`course` row), or in the lesson it was killed in (`saved_lesson`); a player who finished a
  round before any course sees What's new (then placement); a saved first round reopens Free play;
  anyone else gets Welcome, whose Choose a city leads to the start-district picker. Footers end 12 dp above the bar on a tab
  (`bottomActionGap`).
- **Course and lessons:** `coursePlanProvider` builds the open city's course with pindoro_core
  `buildCourse` (one unit per raion) from its saved start raion (`course` table, picked on the
  first open); `courseProvider` adds the lesson results (`courseProgress`). A lesson
  (`LessonController`) plays a `LessonRun` on one screen; every answer and step upserts the one
  `saved_lesson` row (seed, pack version, step and answers), so an app kill resumes it for 24 h:
  `start` re-plans from the seed and replays the answers (pindoro_core `LessonRun.restore`). Leave
  drops it; `ProgressDao.finishLesson` saves the `lesson_result`, its `lesson_answer`s and the Pit
  stop updates (`reviewAnswers`) and drops it, in one transaction. XP, known streets, Welcome and
  Me read lessons too. Lesson complete's Continue sets `pathUnlockProvider`; the Path plays the unlock when it
  shows (Unit complete's Continue plays the next unit opening).
- **First launch:** What's new reads `placementProvider` (known streets → pindoro_core
  `placeLessons`) and `ProgressDao.place` saves each placed lesson as a 0-XP `lesson_result` (kind
  `placed`), so placement needs no table. The picker (`startDistrictsProvider`) writes nothing
  until Start in. A course with no results shows the "Start here" coach mark (`pathCoachProvider`
  hides it for the launch).
- **Road trips:** format 3 packs carry a road graph (`roadGraphProvider`, null for an older pack:
  no road trips). `RouteView` (`features/map`) draws a trip: a one-finger drag that starts near the
  route's end walks pindoro_core `RouteDraft` along the streets (`RouteDrawLayer` joins the gesture
  arena only then, so other drags pan the map), the screen ↔ map math is `MapProjection` (512 dp
  tiles, north up), overlays are `route_layers.dart`; with a screen reader on it shows a turn list.
  A lesson's trip is its step 11 (`TripStep`); the Final drive (`DriveController`) saves each trip
  as its own `lesson_result` (kind `finalDrive`) as soon as it is answered. Trips never reach the
  Pit stop or known streets. Settings → Accessibility → Choose turns from a list (`turn_list`)
  shows the turn list without a screen reader too.
- **Unit guide** (`features/course/ui/unit_guide_screen.dart`): from the signpost's book button or
  a done lesson's See the streets; a map of the unit's streets (`PindoroMap` without controls), a
  tip from pindoro_core `mainAxis` and the unit's stops as rows.
- **Leagues** (`features/league`): an anonymous account (`league_player`: player id, token, name)
  from `POST /v1/players` when the player first joins on the Leagues tab. `standingProvider` sends
  this league week's XP (pindoro_core `leagueWeek`, `ProgressDao.xpBetween`) with
  `PUT /v1/league/me` and returns the ranked league; the server owns ranks, zones and moves. The app
  root listens to it (so it syncs at launch) and invalidates it on resume; opening the tab and the
  end of a round, lesson or road trip invalidate it too. No automatic retry; a 401 drops the account; failures read as offline only when the server
  wasn't reached (`leagueFailure`), else "isn't working right now". Results shows "Up to 4th in
  Avenue league" when the round's XP raised the rank (`rankBefore`). Settings → League renames
  (`/league-name`) and leaves (the server forgets the player). Tests override
  `leagueApiProvider` with a `MockClient`.
- **Badges** (`features/badges`, spec `docs/specs/2026-11-11-badges-design.md`): pindoro_core
  `badgeProgress` is the rule; `readBadgeStats` reads the stats fresh from `ProgressDao`
  (`badgeCounts`, road trips, goal days) and the installed packs of played cities
  (`readInstalledPack`, never a download). `awardBadgesProvider` saves newly earned badges
  (`badge`, insert or ignore) and returns them. End screens (Results, Lesson complete, Unit
  complete) mix in `BadgeMoments`: they award as they open and show a reward sheet per new badge
  after the arrival and any level-up moment (`showBadgesAfter`). The app root awards quietly at
  launch only while there are no badges (past play). Me's shelf reads `badgesProvider`; its New
  pills come from `newBadgesProvider` (taken and marked seen when the Me tab opens; the tab shell
  invalidates it); closing a reward sheet marks that badge seen. `review_cleared` logs Pit stop
  clearings for Pit crew. Badge tests override `packStoreProvider` with a temp-dir store; app
  tests without one get no awards.
- **Hear the name:** `speechProvider` (`core/speech.dart`, `flutter_tts`) reads a new street's name
  in `speechLanguage(name)`; the button shows only when `canSpeakProvider` finds a voice. Tests
  override `speechProvider`.
- **Strings:** every UI string comes from `lib/l10n/app_{en,ka}.arb` (gen-l10n, `context.l10n`);
  `just gen` writes `app_localizations*.dart` (not committed). Georgian is a draft awaiting native
  review.
  Numbers through `formatNumber` (narrow no-break space groups), distances through
  `formatDistance`. Never uppercase.
- **Settings** (`user_settings`, watched by `settingsProvider`): language (null = device),
  street names, theme, sound, haptics, daily goal, reminder, turn list, the league account (plus the first Home's
  coach-mark flag); they apply immediately. `feedbackProvider` plays haptics
  per game event behind the Haptics toggle; the Sound toggle gates nothing until a sound kit exists.
- **Streak:** only goal-met days are stored (`goal_day`, written by `ProgressDao.markGoalIfMet`
  with the answer that reaches the goal, or by `streakProvider` when today's XP already meets it:
  a lowered goal, XP from before R2). `streakProvider` derives the
  streak, freezes and pill state with pindoro_core `streakOf`; the app root refreshes it on
  resume. One reminder is scheduled at a time (`reminderProvider` → `Reminders`, listened to at
  the app root); Settings turns it off and cancels it. Tests override `remindersProvider`: the
  notifications plugin has no platform side there.
- **Pit stop:** `review_item` holds each city's streets to review (step, run of Greats, due day,
  last answer). `recordAnswer` applies pindoro_core `nextReview` in the same transaction: Close
  and Miss bring a street in, two Greats in a row take it out. Readers keep the streets still in
  the pack (`dueIn`). A Pit stop round (`round.pit_stop`) asks up to 10 due streets, most overdue
  first, framed by the districts that hold them; it and retries show the reroute plate with the
  last distance (`previousDistances`).
- **Drift defaults are literals** (`Constant('local')`): drift copies them into the generated
  migration steps, which can't see app enums. No Flutter imports in `database.dart` either.
- **Database:** `database.dart` holds only tables and migrations. Queries live in Drift DAOs
  (`@DriftAccessor`, built without `daos:` so `core` never imports a feature): `SettingsDao`
  (`core/database/`, `settingsDaoProvider`) owns the settings row with typed writes
  (`chooseCity` clears another city's area, `chooseArea`, `chooseDifficulty`, `setTheme`, …);
  `ProgressDao` (`features/progress/data/`, `progressDaoProvider`) owns rounds, planned questions,
  the answer log, goal days and review items, and the rules read from them (saved round, retry
  set, recent streets, today's XP, the Pit stop).
  Screens call these providers, never `databaseProvider`. Client ids are UUIDv7 (`newId()`).
  `answer` is an append-only log, enforced by the `answer_immutable` trigger. Changing a table: bump `schemaVersion`, add a migration, run
  `just gen` (it runs `drift_dev make-migrations`, then build_runner) and commit the new dump in
  `drift_schemas/`. Generated Dart (`*.g.dart`, `database.steps.dart`, `test/drift/**/generated/`)
  is never committed: `just gen` rebuilds it from the dumps, and `just gen-check` fails in CI
  when a dump is missing.
- **Config** only via `--dart-define` (`AppConfig`): `API_BASE_URL`, `TILES_BASE_URL` (pack
  URLs come absolute from the API catalog). Dev defaults use 10.0.2.2 (Android emulator → host);
  on the iOS simulator pass `http://localhost:3000` / `:3001` and start the API with
  `PACKS_PUBLIC_URL=http://localhost:8080`.
  Cleartext HTTP is allowed only in the debug/profile manifests.
- **Updates:** sideloaded installs never update themselves. `appUpdateProvider`
  (`features/pack/data/app_update.dart`) compares the catalog's `app.build` with this build
  (`package_info_plus`); the app root offers the download once per launch and Settings → About
  shows the version. Bump `version` in `pubspec.yaml` for every build handed out.

## Map

- `PindoroMap` loads the bundled style, injects `{TILES_BASE_URL}` (Martin source `georgia`), and
  always shows "© OpenStreetMap contributors, Protomaps". Never point it at public OSM tile servers.
- GeoJSON source names: `you-pin` (a symbol of the `PinMark` rendered to PNG, anchored at its tip),
  `truth-street` (8 dp yellow over a 12 dp ink casing), `measure` (dotted ink) + `measure-end`
  (ring), `area-mask` (dims outside the round's area). The map owns its controls (my location,
  recentre, zoom) and the attribution chip, placed above `bottomInset`.
- **Round screens** (`features/quiz`, `features/results`): `/round` is one route for setup states, question and
  reveal; Results (`results_data.dart` gathers everything), the per-answer street view and the
  full-screen level up.
- Colour rule: **yellow = truth, cobalt = you, ink = measurement.** Never swap them.
- Screens get the map through `pindoroMapBuilderProvider`; tests override it to capture the
  `PindoroMap` config instead of building the platform view.
- Overlay layers are added with `enableInteraction: false`: maplibre_gl turns taps on interactive
  layers into feature taps, and no pin would drop.
