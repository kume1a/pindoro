# Drive tab Implementation Plan

> **For agentic workers:** Implement this plan one task at a time. Steps use checkbox (`- [ ]`)
> syntax for tracking.

**Goal:** A Drive tab, first in the bar and the page the app opens on, from which a drive starts in
two taps (spec: `docs/specs/2026-11-22-drive-tab-design.md`).

**Architecture:** The tab (`/drive`) is a launcher over the existing drive flow, which moves to
`/drive/go`. One `WhereTo` widget (search, Home and Work tiles, run, Surprise me, Recent) serves the
tab and the flow's own Where to page; the tab adds the drive cards moved from Today and Past drives.
Minutes to Home and Work come from a provider that locates without asking and plans with the same
`planNav` the flow uses.

**Tech Stack:** Flutter, Riverpod 3 (no codegen), go_router `StatefulShellRoute`, pindoro_design,
pindoro_learning `planNav`.

## Global Constraints

- New UI uses pindoro_design widgets and tokens only; no new design-system parts.
- Never uppercase UI strings; every string from `app_{en,ka}.arb`, English first.
- Layers: screen features never import each other; `ui/` never imports Drift.
- The tab never asks for location; only the flow does (as now).
- Run only the tests that cover the change.
