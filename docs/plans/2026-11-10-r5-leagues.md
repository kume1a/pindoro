# R5 Leagues Implementation Plan

> **For agentic workers:** Implement this plan one task at a time. Steps use checkbox (`- [ ]`)
> syntax for tracking. Commits need the user's approval each time (`~/.claude/CLAUDE.md`): build
> the tasks, then ask before committing them, one commit per task.

**Goal:** Weekly leagues of up to 30 players ranked by this week's XP, on anonymous accounts.

**Architecture:** The API owns players, leagues and moves (Fastify module `leagues`, three Drizzle
tables, lazy weekly rollover). The app keeps a token in a one-row Drift table, sums its week's XP
locally and `PUT`s it; the reply is the whole league. The week and name rules exist in Dart and TS,
checked by one shared fixture.

**Tech Stack:** Fastify 5 + TypeBox + Drizzle + PostGIS, `@fastify/rate-limit`, vitest; Dart 3 /
Flutter 3.47.9, Riverpod 3 (no codegen), go_router, Drift, package:http, gen-l10n.

## Global Constraints

- Spec: `docs/specs/2026-11-10-r5-leagues-design.md`.
- Week: Monday 00:00 at UTC+4, key = the Monday's `YYYY-MM-DD`. Names 2–20 code points.
- League size 30, top 5 up, ranks 26+ down; six tiers (0 Alley … 5 Highway).
- API: response shapes are TypeBox schemas; `just openapi` and `db:generate` committed; modules
  never import each other.
- App: schema 10 with its dump committed; every string in `app_en.arb` + `app_ka.arb`; never
  uppercase; `ui/` never imports Drift; the new `features/league` layer sits between `course` and
  the screen features in `test/architecture_test.dart`.
- Design values from tokens only (app-only ones in `tokens/app.json`); goldens via `just goldens`.
- Run only the touched tests locally; CI runs the rest. No ticket ids in comments.
